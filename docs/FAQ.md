# 常见问题（FAQ）

## 功能相关

### 去水印是 AI 修复吗？能还原水印下面的画面吗？

不是。本工具提供三种**遮挡**方式：模糊、马赛克、纯色块。它会重新编码整段视频，把指定区域覆盖掉，但不会“推测”或“生成”被水印挡住的原始内容。

如果你需要内容修复（inpainting），需要使用专门的分割 + 生成式模型；这类方案的模型体积、算力和不可控性都远高于本地滤镜处理，因此没有纳入第一版。

### 水印会移动 / 缩放，怎么办？

当前每个区域在整个视频中位置固定。可以：

- 添加多个区域覆盖不同位置；
- 把区域画大一些，覆盖水印所有可能出现的位置；
- 如果水印只出现在部分时间段，当前版本不支持按时间启用区域（后续可以扩展）。

### 拼接后的分辨率为什么变成 1280×720 / 720×1280？

当素材参数不一致时，需要统一画布：

- 横屏最大 1280×720；
- 竖屏最大 720×1280；
- 小于上限时保持原尺寸。

所有素材都是相同参数（同为 H.264、同分辨率、同帧率、同音轨格式）时，会直接无损拼接，不会缩放。

### 拼接后的帧率为什么是 30fps？

标准化路径统一为 30fps，以保证不同素材可以稳定合并。如果所有素材本身就是相同帧率且可无损拼接，则会保持原帧率。

需要保留 60fps 时，请准备参数一致的素材以走无损路径。

### 没有音轨的视频可以拼接吗？

可以。标准化路径会自动补一条静音音轨；无损路径则要求所有素材都有音轨或都没有音轨。

### 支持哪些输入格式？

取决于 FFmpeg 的解码能力，常见包括 MP4、MOV、M4V、WebM、MKV、AVI、FLV、WMV、TS、M2TS、3GP、OGV 等。

界面预览依赖 Chromium：MKV、部分 AVI/HEVC 可能无法预览，但处理仍由 FFmpeg 完成，通常不受影响。

### 输出是什么格式？

- 视频拼接：MP4（H.264 / AAC，faststart）。
- 视频去水印：MP4（H.264 / 原音频可 copy 则 copy，否则 AAC）。
- 去水印保持原分辨率与帧率；拼接标准化路径限制在 720p 级别。

第一版不支持输出 HEVC、AV1、ProRes 或 WebM。需要的话可以在 `ffmpeg/` 的编码参数中扩展。

### 为什么处理后的文件比原片大 / 小？

去水印：

- 已知源视频码率时，会按源码率 + VBV 约束编码，尽量贴近原体积。
- 硬件编码器（尤其 VideoToolbox）的码率控制与 x264 不完全一致，成片可能有 ±5–20% 的波动。
- 源片如果是高压缩效率的编码（例如极低码率的 H.265），重新编码为 H.264 后体积可能变大。

拼接：

- 无损路径：体积基本等于各段之和。
- 标准化路径：按统一画布重新编码，体积会变化。

### 能否处理超过 2GB 的视频？

可以。桌面版不受浏览器内存限制，大小主要取决于磁盘空间与处理时间。超过 2GB 时会提示耗时较长，但不会阻止处理。

应用仍会在处理前用临时文件写中间结果，请确保输出盘和系统临时目录有足够空间。

### 可以同时处理多个任务吗？

不能。当前版本同一时间只允许一个 FFmpeg 任务，避免多个转码争抢 CPU/磁盘。第二个任务会提示先等待或取消。

### 支持 HDR / 10-bit 视频吗？

可以读取和转码，但输出统一为 8-bit `yuv420p`，HDR 元数据与 10-bit 色深不会保留。当前版本面向常见 SDR 视频；若需要 HDR 工作流，建议使用专业工具或等待后续版本。

### 4K 视频能处理吗？

可以，但：

- 去水印保持原分辨率，4K 转码会更耗时；
- 拼接标准化路径会缩放到 720p 级别；
- 建议先用短片段测试，并优先开启硬件加速。

### 支持 Linux 吗？

开发模式可以运行，但第一版没有提供 Linux 安装包。欢迎贡献 AppImage/deb 配置。

### 支持 Windows ARM64 吗？

第一版 Windows 安装包仅提供 x64。Apple Silicon macOS 提供原生 arm64 包。

## 性能相关

### 为什么说比网页版快？

网页版运行 FFmpeg 的 WebAssembly 版本，受浏览器：

- 单线程/SharedArrayBuffer 限制；
- 内存上限与垃圾回收；
- 不能使用本机硬件编码器；
- 文件需要先在 JS 与 WASM 之间复制。

桌面版直接 `spawn` 本机编译的 FFmpeg，可使用多核与 VideoToolbox / NVENC / Quick Sync / AMF。具体提升取决于素材与硬件，通常会明显更快。

### 硬件加速显示“未检测到”？

可能原因：

- 当前 FFmpeg 构建没有编译该编码器（当前内置构建：macOS 包含 VideoToolbox，Windows 包含 NVENC / Quick Sync / AMF）；
- 机器没有对应硬件（例如没有 NVIDIA 显卡就不会有 NVENC）；
- 驱动/系统版本不支持。

应用会用一次真实小视频编码来验证，而不是只看 `-encoders` 列表。检测不到时会自动使用 `libx264`。

你可以在设置页指定自己编译的 FFmpeg（包含所需编码器）后重新检测。

### 开启硬件加速后画质变差？

硬件编码器在低码率下的画质可能略逊于 x264，且码率控制策略不同。对画质敏感时：

1. 在去水印页选择“精细”；
2. 或在设置中关闭硬件加速，使用 `libx264`。

### 处理时电脑很烫 / 风扇很响？

转码会持续占用 CPU/GPU。硬件编码通常功耗更低、速度更快；软件编码会跑满多核。建议接通电源、保持通风，处理长视频前关闭其他重负载程序。

### 为什么预览时进度条拖动有点卡？

预览需要解码并逐帧绘制 Canvas。高分辨率视频在大窗口下会更吃资源。处理本身不受影响。

## 安装与打包

### macOS 提示“无法验证开发者”或“应用已损坏”

当前发布包默认未签名、未公证：

```bash
xattr -dr com.apple.quarantine "/Applications/Local Video Lab.app"
```

或在 Finder 中右键应用 → 打开。

如果你自行构建并希望彻底消除提示，请参考 [BUILD.md](BUILD.md) 的签名与公证章节。

### Windows 提示“Windows 已保护你的电脑”

安装包未签名。点击 **更多信息 → 仍要运行**。

### 安装包有多大？为什么这么大？

主要是 Electron 运行时和 FFmpeg / FFprobe 静态二进制。macOS 安装包通常 140–180MB。详细构成见 [BUILD.md](BUILD.md#11-产物与体积)。

### 如何从源码构建？

```bash
npm install
npm run test:smoke
npm run dist:mac:arm64   # 或 dist:mac:x64 / dist:win
```

完整说明见 [BUILD.md](BUILD.md)。

### 可以打一个同时支持 Intel 和 Apple Silicon 的 universal 包吗？

当前不支持。FFmpeg / FFprobe 需要与架构匹配，universal 包需要把两个架构的二进制合并成 fat binary，构建过程更复杂且容易出错。项目选择分别发布 arm64 与 x64 安装包。

### 打包时下载 FFmpeg 失败怎么办？

`before-pack.cjs` 会重试 3 次。仍失败时，可以手动下载并放入 `.cache/binaries/`：

```text
ffmpeg-darwin-x64
ffprobe-darwin-x64
ffmpeg-darwin-arm64
ffprobe-darwin-arm64
ffmpeg-win32-x64.exe
ffprobe-win32-x64.exe
```

文件名必须与上述格式一致。下载地址见 [BUILD.md](BUILD.md#12-故障排查)。

## 隐私与数据

### 会上传视频吗？

不会。应用没有任何上传接口，运行时不发起网络请求。你可以断网使用。

### 会收集使用数据吗？

不会。没有遥测、崩溃上报或账号系统。

### 设置保存在哪里？

- macOS：`~/Library/Application Support/Local Video Lab/settings.json`
- Windows：`%APPDATA%\Local Video Lab\settings.json`

设置页底部会显示实际目录。删除该文件即可恢复默认设置。

### 临时文件会残留吗？

正常完成或取消都会自动清理。应用异常退出可能留下系统临时目录中的 `local-video-lab-*` 目录；下次启动 24 小时后会自动清理，也可在设置页手动清理。

### 处理结果在哪里？

在每次点击“开始处理/开始拼接”时弹出的保存对话框中选择。应用会记住上次使用的目录。完成后可点击“在文件夹中显示”。

## 故障排查

### 提示“找不到 FFmpeg 可执行文件”

1. 打开设置，确认引擎状态；
2. 如果使用自定义路径，点击“测试路径”或“恢复内置”；
3. 打包版可运行 `--self-test` 检查 `resources/bin`；
4. 重新安装应用。

### 任务进度长时间停在某个百分比

可能原因：

- FFmpeg 正在处理复杂的滤镜图或等待磁盘写入；
- 视频文件位于网络盘/移动硬盘，读取很慢；
- 硬件编码器初始化卡住。

可以先等待 1–2 分钟；仍无变化时取消任务并查看是否换成软件编码后重试。

若问题可复现，请附上：操作系统与版本、视频的 `ffprobe` 信息、设置页引擎截图、任务卡住的百分比。

### 输出文件无法播放 / 花屏

- 确认输出文件完整（任务未取消且成功结束）；
- 尝试用 VLC 播放；
- 如果只有拼接结果异常，尝试换用参数一致的素材，或反馈素材信息。

本项目在冒烟测试中会校验输出编码、分辨率、音轨和时长，但仍可能遇到特殊素材。

### 应用启动白屏

1. 确认使用 `npm run build` 后的产物，而不是开发服务器；
2. 打开开发者工具（开发模式）查看 CSP 或脚本错误；
3. 检查是否修改了 `index.html` 的 CSP 而未加入所需来源。

### 预览无法播放，但处理成功

说明 Chromium 不支持该编码/容器，而 FFmpeg 支持。预览失败不影响处理，只是无法所见即所得地框选。建议先用系统播放器确认水印位置再盲选。

### 如何反馈问题？

在 GitHub Issues 中提供：

- 应用版本、操作系统、芯片（Intel / Apple Silicon）；
- 设置页引擎状态截图；
- 复现步骤；
- 如涉及媒体兼容性，附 `ffprobe` 输出（不需要上传完整视频）。
